Krantho is a CMS library: you add it to a site you build yourself, and it runs inside your app, on your host and your database. Version 1.0 is the first public release and the first on npm. Krantho grew through a series of 0.x releases in a private repository; this entry gathers what they built, and the changelog starts here.

## Content

- **Content templates in code.** A collection is a Zod schema in `krantho.collections.ts`. The schema is the form editors fill in, and your page templates render the documents. Code-defined fields are read-only; fields added at runtime extend them.
- **Markdown in your repository.** Documents are markdown with frontmatter. A new database imports them on first start, and every deploy imports new and changed files after that. A page an editor changed in production keeps the editor's version, and a deploy fails rather than overwrite it.
- **Production edits back to git.** Changes made in Studio come back to your repository as a branch you review and merge, so the files and the database stay one source.
- **Drafts and versions.** Saving keeps the live page as it is; publishing promotes the saved version. Every version is kept, with edit locks while someone works on a page. A page's metadata, its SEO included, is saved and versioned with it.
- **Locales**, with locale-aware content and API filtering.
- **A media library** with folders, tags, crop and hotspots, and an image optimizer that serves sized WebP and AVIF versions.

## Studio

- **One dashboard on every framework.** Studio is a prebuilt React app your server serves at `/studio`, the same on Next.js, SvelteKit and Express.
- **Pulse, Site, Structure, Media and Setup.** What needs attention, every page with its status and locales, the site's structured data, the media library, and collections, locales, AI providers, webhooks and people.
- **Three ways to edit a page.** Live mode edits the page as your site renders it. Structure mode is the form made from the schema. Data mode shows the search and sharing previews, the page's JSON-LD graph with where each value comes from, and its history.
- **Preview on the site.** An editor sees a draft on the page itself before publishing.
- **The assistant.** A chat beside any page, on the language model you configure.

## Structured SEO

- **Archetypes at four scopes.** Site, collection, route and document archetypes compose one cross-linked JSON-LD graph per page, with breadcrumbs that match the page.
- **Checked as you go.** Structured data is checked against Schema.org and each search engine's published rules, before start, before a build and at publish.
- **Meta tags, Open Graph, the sitemap, `robots.txt` and `llms.txt`** come from the same configuration. Each page in the sitemap carries its own last-modified date, and search engines that use IndexNow hear about a page when it is published.
- **Enrichment with your own provider.** A language model fills missing meta descriptions and Schema.org properties from what the page states, and never overwrites what an editor wrote. Anthropic, OpenAI, Gemini, OpenRouter and Ollama, through `@krantho/ai`, a client with no dependencies.

## Hosting

- **Your database.** SQLite by default, Postgres in production, with migrations that run themselves.
- **Your media store.** Local disk, Vercel Blob, an S3-compatible store or Google Cloud Storage.
- **Pages cached until they change.** Next.js pages are kept until a change invalidates them, optionally in a cache shared by several instances. SvelteKit and Express pages are kept at CloudFront, Cloud CDN or Vercel and purged by tag.
- **Pages read in-process.** Page templates read the published version straight from the database, with paged lists that need no bodies.
- **One typed configuration** from `krantho.config.ts` and the environment.

## For developers

- **One install per framework:** `@krantho/next`, `@krantho/sveltekit` or `@krantho/node`, and `create-krantho` for a new project.
- **A REST API** described by an OpenAPI 3.1 specification, with plugins, webhooks with retries, and sign-in by token or OpenID Connect. CI jobs can call it with their platform identity instead of a stored secret.
- **UI packages** for React, MUI, Tailwind and Svelte.
- **The `krantho` command line** for content, schema, SEO and snapshots, and the Claude Code plugin with skills for building a krantho site.
