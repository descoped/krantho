A minor release that adds a third way to run krantho: markdown in your repository, built to plain files.

## Added

- **Static sites.** `@krantho/static` builds a site from its markdown at build time: every page with its structured data, the sitemap, llms.txt and robots.txt. There is no database, API or Studio, so the output deploys to GitHub Pages or any file host. See [Deploy to GitHub Pages](/docs/deploy-github-pages).
- **A static starter.** `create-krantho` has a "Static site (Next.js, GitHub Pages)" choice: a docs site with a grouped sidebar and a workflow that publishes it on every push.
- **Links under a base path.** Links and images in markdown that start at the site's root get the path the site is served under, as Next's own links do.
- **The SEO files without a request.** `@krantho/api` exports the builders behind the sitemap, robots.txt and llms.txt.

## Fixed

- **Structured data on the filesystem provider.** Pages compose the identity and archetypes the `seo` section configures. Before, they fell back to a generic article.
- **Dates from git.** A file is dated by its last commit, so publish dates and the sitemap's `lastmod` stay the same from one checkout to the next.
